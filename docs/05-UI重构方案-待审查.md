## 1. 现状诊断

所有结论都对着代码/截图核过，不是感觉。

### 1.1 设计令牌：表面层级跨度太大

| 令牌 | 当前值 | 相邻亮度差 | 问题 |
|---|---|---|---|
| `--bg` | `#0a0d12` | — | 偏蓝很重（B 比 R 高 8）|
| `--bg-1` | `#0f141c` | B +10 | |
| `--bg-2` | `#141b25` | B +9 | |
| `--bg-3` | `#1c2532` | B +13 | 与 bg-2 差 13，跳跃明显 |

**对照 Linear**：它的整个表面体系只在亮度 `8 → 9 → 15 → 18 → 22` 之间游走，**相邻差 1~4**。
手法是「靠表面微差表达层级，而不是靠留白和阴影」。我们的跨度是它的 2~3 倍，所以看起来
是「一块一块的色带」，而不是「层层浮起」。

### 1.2 设计令牌：强调色太多

当前同时存在 **6 个彩色强调**：`--accent`(亮蓝) `--cyan` `--green` `--amber` `--rose` `--violet`，
再加 10 个分类色。**同一个界面里 16 种颜色在抢注意力**，没有主次。

**对照 Linear**：整套系统**几乎全无彩色**，文字层级靠白色透明度（`#F7F8F8` → `#D0D6E0` → `#8A8F98`），
**只用 1 个**低饱和靛蓝 `rgb(94,106,210)` 做强调。

### 1.3 设计令牌：圆角没有统一尺度

| 元素 | 当前圆角 |
|---|---|
| `.card` | 14px |
| `.btn` | 9px |
| `.badge` | 6px |
| `.chip` | 999px |
| 弹窗 | 各处不一 |

**对照 Linear**：`2px`(内联) → `4px`(chip) → `6px`(按钮/输入) → `8px`(卡片/弹窗)，
**最大只到 8px**，且每个尺寸有明确用途。我们最大 14px，偏"软"。

### 1.4 排版：字号是散的，且偏小

代码里出现的字号：`9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14.5 / 15 / 16.5 / 17 / 21`
—— **14 个不同字号，没有模数关系**。

技能库的硬性规则：**正文不得小于 12px**。我们大量使用 9.5~11.5px（阶段标签、元信息、统计等）。

**对照 Linear 的字阶**：`12.25(代码) / 13(按钮) / 14(链接) / 15(段落) / 16(正文) / 20(h3) / 24 / 40 / 64`
—— 只有 9 档，且每档有明确角色。它的关键手法是**用字重（510/590）而不是字号**区分层级。

### 1.5 布局：三栏固定宽度，没有响应式

```
┌────────┬──────────────────────┬─────────────┐
│ 248px  │      flex:1          │    500px    │
│  侧栏   │       信息流          │   AI/详情    │
└────────┴──────────────────────┴─────────────┘
```

- **固定 px 宽度**，窗口变窄时中间被压到变形（技能库列为 High 级问题：禁止固定 px 容器）
- 右侧 500px 占比过大，实际内容区被挤压
- 侧栏 248px 里塞了：5 个导航 + 一键补齐 + 任务面板 + 10 个分类 + 热门标签 —— **层级过深**

### 1.6 信息层级：卡片信息一次性全给

每条帖子卡片当前同时呈现：分类色块 · 价值分 · 羊毛角标 · 来源数 · 频道 · 日期 ·
正文 · 标签 · 域名 · 阅读数。**一屏扫过去没有主次。**

技能库原则：**渐进披露（Progressive Disclosure）** —— 先给判断所需的最小信息，细节按需展开。

### 1.7 规范性：用 emoji 当结构图标

当前用了 `📡 ⭐ ✨ 🔗 🔔 ⟳ ★ ⚙️` 等。

技能库**明确列为反面模式**：
> Emoji are font-dependent, inconsistent across platforms, and cannot be controlled via design tokens.

项目其实**已经装了 `lucide-react`**（我在 package.json 里看到过），只是没用上。

## 2. 参考基准

### 2.1 Linear 的六个可复用手法

| 手法 | 具体做法 | 我们能怎么用 |
|---|---|---|
| **表面微差** | 相邻层只差 1~4 亮度 | 把 4 层改成一串小步长 |
| **透明度分层** | 文字用 `rgba(255,255,255,α)`，不用不同色相 | 元信息/正文/标题用同一色的不同透明度 |
| **510/590 字重** | 用字重而非字号做层级 | 标题用 600，正文 400，元信息 400+降透明 |
| **单一强调色** | 全局只有 1 个低饱和靛蓝 | 保留 1 个主色，功能色只在真正需要时出现 |
| **圆角 ≤8px** | 最大 8px，尺寸有用途 | 收敛成 4/6/8 三档 |
| **发光边框** | `0 0 0 1px rgba(0,0,0,.33)` 当边框 | 用 ring 阴影替代硬边框 |

### 2.2 技能库的硬性清单（交付前必须全过）

- [ ] 不用 emoji 当图标（用 SVG / lucide）
- [ ] 正文不小于 12px，行高 1.5+
- [ ] 对比度 4.5:1（正文）/ 3:1（大字）
- [ ] 可点元素要有 `cursor: pointer`、hover 态、150–300ms 过渡
- [ ] 键盘焦点可见（不能去掉 focus ring）
- [ ] 尊重 `prefers-reduced-motion`
- [ ] 响应式断点 375 / 768 / 1024 / 1440
- [ ] 不用颜色单独传达信息（配色 + 图标/文字）
- [ ] 异步内容预留空间，避免布局跳动

## 3. 改造方案

### 3.1 设计令牌（逐项 前 → 后）

**深色表面**（步长从 10~13 收到 3~4）

| 令牌 | 现在 | 建议 | 用途 |
|---|---|---|---|
| `--bg` | `#0a0d12` | `#08090a` | 页面底色（近乎中性的黑，去蓝） |
| `--bg-1` | `#0f141c` | `#0d0e10` | 侧栏 / 框架 |
| `--bg-2` | `#141b25` | `#121316` | 卡片 |
| `--bg-3` | `#1c2532` | `#191a1e` | hover / 选中 |
| `--bg-4` | — | `#1f2024` | 输入框 / 最高层 |

**文字**（改用透明度分层，去掉蓝灰）

| 令牌 | 现在 | 建议 |
|---|---|---|
| `--fg` | `#e9eff7` | `#f7f8f8`（主） |
| `--fg-dim` | `#96a4b6` | `#a8adb8`（次） |
| `--fg-mute` | `#6a788a` | `#7c818c`（辅助） |

**强调色**（6 个 → 1 主 + 3 功能）

| 用途 | 现在 | 建议 |
|---|---|---|
| 主强调 | `#4cc2ff` 亮蓝 | `#5e6ad2` 低饱和靛蓝（Linear 同款气质） |
| 成功/免费 | `--green` | 保留 `#3fb950` |
| 警告/限时 | `--amber` | 保留 `#d29922` |
| 危险/风险 | `--rose` | 保留 `#f85149` |
| ~~`--violet`~~ | 并入主强调 | 取消独立色 |
| ~~`--cyan`~~ | 并入主强调 | 取消独立色 |

10 个分类色**大幅降饱和**（如 `#e0605a` → `#8a6a68`），只做微弱的色相提示。

**圆角**（收敛成 3 档）

| 档位 | 值 | 用途 |
|---|---|---|
| `--r-sm` | 4px | chip、badge、内联代码 |
| `--r-md` | 6px | 按钮、输入框 |
| `--r-lg` | 8px | 卡片、弹窗 |

**字阶**（14 档 → 9 档）

| 角色 | 字号 | 字重 | 行高 |
|---|---|---|---|
| 页面标题 | 20px | 600 | 1.3 |
| 区块标题 | 16px | 600 | 1.4 |
| 卡片标题 | 15px | 600 | 1.45 |
| **正文** | **14px** | 400 | **1.65** |
| 卡片正文 | 13.5px | 400 | 1.6 |
| 按钮 | 13px | 500 | 1.4 |
| 元信息 | 12px | 400 | 1.5 |
| 微标签 | 11px | 500 | 1.4 |
| 数字/代码 | 13px | 500 | 1.4 |

> **取消所有 9.5~11px 的正文字号。** 微标签最低 11px 且只用于非关键信息。

### 3.2 布局重编排

**问题**：三栏固定 px，右侧 500px 太宽，侧栏塞太多。

**方案 A（保守）**：保持三栏，但
- 侧栏 248 → **220px**，并把「热门标签」移到主内容区顶部
- 右侧 500 → **420px**，且**可拖拽调宽**
- 中间加 `min-width: 480px`，窗口不够时右侧自动收起

**方案 B（推荐）**：三栏 → **「窄导航 + 主内容 + 可收起详情」**
```
┌──────┬────────────────────────────┬──────────────┐
│ 64px │  筛选栏（顶，56px）           │  详情/AI      │
│ 图标 ├────────────────────────────┤  480px        │
│ 导航 │  信息流（列表式，非卡片）      │  (可收起)      │
│      │                            │              │
└──────┴────────────────────────────┴──────────────┘
       └ 分类/标签 移到左侧抽屉，或顶部下拉
```
- 左侧 64px 纯图标导航 + tooltip，hover 展开成 220px 覆盖层（不挤压内容）
- 分类不再常驻侧栏，改为**顶部下拉筛选**（当前筛选显示为一排 chip）
- 右侧默认收起，点帖子才滑出

**方案 C（激进）**：完全列表化 + 命令面板驱动
- 侧栏和右侧栏都取消，主内容满宽
- 一切导航走 Ctrl+K（已实现）
- 详情用**底部抽屉**或**全屏覆盖**

### 3.3 信息层级（详略得当）

**帖子卡片**改为三级呈现：

**折叠态（默认，一行半）**
```
● 分类名   正文前 60 字…                      2 个来源 · 22 天前
```
只保留：分类色点 + 正文摘要 + 来源数 + 时间。**去掉**：标签、域名、阅读数、价值分数字。

**悬停 / 键盘选中**
```
● 羊毛优惠   X premium 官方限时优惠 40% 啦！…
   免费 · 限时 · 开源                     github.com · 102 阅读 · ★ 7.9
```
补上标签、域名、阅读数、价值分。

**展开（详情面板）**
保留现在的完整信息 + 相关链接 + 同事件来源 + 相关推荐。

**价值分**从「数字」改为「**小圆点进度**」或直接只做排序依据不显示——数字对用户没有直觉意义。

### 3.4 图标系统

- 用已安装的 **lucide-react** 替换全部 emoji
- 统一尺寸令牌：`14px`(行内) / `16px`(按钮) / `18px`(导航)
- 统一线宽 1.5px
- 同一层级只用一种风格（全线性，不用填充）

对应关系：`📡→Radio` `⭐→Star` `✨→Sparkles` `🔗→Link2` `🔔→Bell` `⟳→RefreshCw` `⚙️→Settings`

### 3.5 响应式

| 断点 | 布局 |
|---|---|
| ≥1440px | 完整三栏 |
| 1024–1440 | 三栏，右栏 420px |
| 768–1024 | 两栏，右栏变覆盖式抽屉 |
| < 768 | 单栏，筛选与详情都是抽屉 |

## 4. 分阶段实施

| 阶段 | 内容 | 风险 | 可见变化 |
|---|---|---|---|
| **P1** | 设计令牌（色/圆角/字阶）+ 图标替换 | 低（纯 CSS/替换） | 全局气质变化 |
| **P2** | 卡片信息分层（折叠/悬停/展开） | 中 | 信息流疏密感 |
| **P3** | 布局重编排（选定方案） | 中高 | 结构变化 |
| **P4** | 响应式 + 可访问性收尾 | 低 | 窄屏可用 |

每阶段可单独验收、单独回滚。
