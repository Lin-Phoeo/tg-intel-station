# 本地简报按需筛选设计

**状态：** 用户已在对话中确认筛选方式与时间范围。本文记录已批准的设计，供实现计划引用。

## 目标

用户可在「今日简报」里临时选择筛选条件，预览匹配候选，并生成只含所选条件结果的本地简报。临时条件不覆盖日报自动任务使用的已保存设置。

## 用户流程

- 简报面板加载现有日报设置，作为本次筛选初值：标签、最低价值分、窗口天数。
- 可选分类、频道、标签、最低价值分与时间范围。
- 时间快捷项：近 7 天、近 30 天、近 1 年、全部时间；另允许自定义开始/结束日期。
- 用户点击「预览候选」后查看匹配条目与数量；可调整条件并再次预览。
- 用户可按条目勾选或取消，默认全选当前预览候选。
- 用户点击「生成本次简报」时，服务端按筛选条件重新检索，再与选中的 ID 求交集，按价值排序并应用已有条数上限；不得信任前端提交的帖子正文或筛选结果。
- 手动生成的筛选简报显示于面板并可导出 Markdown；不改变自动日报配置、pushedIds、自动生成日期或自动调度状态。
- 现有「立即生成」保留为快捷操作，使用默认已保存条件并选中全部候选。

## 范围与数据契约

- 复用 `bot.selectDigestItems()` 及 store 现有 `category/channel/tags/from/to/minValue` 筛选语义。
- 手动预览与生成限定为当前数据库查询结果及既有 `pushLimit` 上限，不支持任意全文搜索或 RAG 查询。
- 将手动生成结果仅保存在当前界面状态，不覆盖服务端 `briefing:latest`，避免用户筛选日报覆盖每天自动简报；本次生成仍可弹桌面通知，但通知内容只摘要所选结果。
- 分类/频道选项来自现有 `/api/facets`；标签来自同接口的热门标签。时间和分数由界面控件表达。
- API 只接收筛选条件和所选 ID；服务端在可筛选候选集合内验证 ID，并从数据库取正文。

## 非目标

- 不改 Telegram 推送、机器人配置、日报自动生成、定时器、pushedIds、检索/RAG算法。
- 不新增数据库表或 npm 依赖。
- 不做任意长历史报告、收藏报告、定时筛选报告或 AI 裁判。

## 验收标准

- 近 7 天、近 30 天、近 1 年、全部时间及自定义日期范围均与服务端筛选结果一致，日期边界包含起止日。
- 分类、频道、标签、最低分组合筛选使用现有 AND 语义；未选择值不增加限制。
- 预览候选可全选、全不选、逐项勾选；生成结果仅包含被选且仍符合最新服务端筛选的 ID，恶意或过期 ID 被忽略。
- 手动筛选生成不覆盖自动简报存储、不修改 bot.json、不变更 pushedIds 和调度状态。
- 空结果、有候选但全部取消、服务错误均显示明确状态；导出只含本次生成结果。
- 用临时数据库测试端点与筛选交集；生产代码改动后运行 `npm test` 与 `npm run build:web`，并用浏览器验证完整筛选、预览、勾选、生成、导出路径。
